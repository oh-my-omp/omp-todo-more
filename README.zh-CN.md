# omp-todo-ng

[English](README.md) | 简体中文

- **`todo` 工具**
  - `todo` 工具注册 — 功能：注册名为 `todo` 的工具，遮蔽宿主同名内置工具，接收扁平 JSON 参数（`goal`、`add`、`start_id`、`explain`、`estimate`、带可选 `commit` 的 `done_id`、`drop_ids` 或 `view`），作用于携带目标、稳定条目 ID（`t1`、`t2`…）、逐项说明、分钟预算与按状态记录的进度时间的分阶段列表。调用 `todo({})` 或 `todo({ view })` 以只读方式查看完整、活跃或单阶段视图；变更调用返回带条目 ID、当前时间与活跃项截止时刻的紧凑活跃视图。时机：在插件已加载的会话中，模型每次调用 `todo` 时。实例：`index.ts` 的 `pi.registerTool(TODO_TOOL_DEFINITION)`；查看用 `{}` / `{ view: "current" }`，变更形如 `{ goal: { title, summary, acceptance }, add: [{ phase, title, detail, minutes }] }`。
  - 工具字段声明 — 功能：声明 `loadMode: "essential"`、`approval: "read"`（兼容 Plan Mode）、`concurrency: "exclusive"` 与 `mergeCallAndResult: true`，使工具默认可见、串行执行，且结果卡片替换调用卡片。时机：插件加载注册工具时固定。实例：`index.ts` 的 `TOOL_FIELDS`。
  - 说明与卡片渲染 — 功能：携带不超过 200 字符的简明描述（浓缩分阶段工作、逐项 `leafMaxMinutes` 上限与 `todo({})` / `todo({ view })` 查看），以及返回 pi-tui 节点的 `renderCall`/`renderResult` 钩子——先是未提交的参数预览，之后是目标与阶段、条目的 `checklist`（折叠时只列本次变化的条目，展开时列全部）——omp 把它们画成 `todo` 卡片的正文，终端里与 Tern 原生界面里都一样，卡片头是宿主的 `Todo 已完成/总数`。时机：每当提供 `todo` 时出现在 prompt 的 tools 部分，以及渲染 `todo` 调用或结果卡片时。实例：`src/tool.ts` 的 `DESCRIPTION`，`src/native.ts` 的 `renderTodoCall`/`renderTodoResult`。
  - 批次校验 — 功能：在应用任何变更之前原子校验整批参数：非空目标/任务字段、唯一标题、受 `leafMaxMinutes`（默认 60）约束的正整数分钟数、有效条目 ID，以及 `commit` 只能与完成一个未关闭条目的 `done_id` 同时出现。时机：每次 `todo` 调用，在任何状态变更之前。`add` 在校验前分配 ID，同一调用里的 `start_id`、`explain`、`estimate`、`done_id` 与 `drop_ids` 可以引用这些 ID。实例：`src/kernel.ts` 的 `validate`/`overCap` 产生 `Task "…" estimate 90 min exceeds the 60-minute limit for one item`。
  - 完结后开始新一轮 — 功能：全部条目都已完成或放弃后，带 `add` 的调用不再追加，而是开始新的一轮：上一轮的目标与条目不带入，ID 从 `t1` 重新分配；这样的调用必须同时带 `goal`，否则整次调用被拒。不带 `add` 的调用仍作用于已完结的列表。时机：列表没有 `pending` 或 `in_progress` 条目时带 `add` 的 `todo` 调用。实例：`src/kernel.ts` 的 `planTodo` 与 `roundOf`；单独的 `{ add: [...] }` 被拒，错误为 `Every item of this list is completed or abandoned, so add starts a new round … provide goal together with add`。
  - 迁移管线 — 功能：每次 `todo` 变更都按固定阶段执行：调用的结构规划、尾项变换、同步守卫（尾项生命周期、超时估时锁）、异步验收守卫，最后是完成提交守卫；全部放行之后才写入列表。第一个拒绝或异常就让整次调用以 `isError` 失败，后续守卫一律不再执行，宿主列表、说明记录与 git 保持原样；放行的守卫可以给结果附一条说明，或附一个在写入列表时应用的状态变更（提交记录）。异步守卫收到工具调用的 `AbortSignal` 与 `ExtensionContext`；每次拒绝都带守卫名记一条警告。时机：项目配置解析成功后，每个会改变列表的 `todo` 调用。实例：`src/pipeline.ts` 的 `planTransition`/`runGuards`，守卫类型见 `src/guard.ts`，规划见 `src/kernel.ts`；守卫抛异常时报 `Guard "<name>" failed: <message>`。
  - 超时估时锁 — 功能：条目的预算已收到超时警告时，拒绝改动其分钟数的 `estimate`，并提示把剩余工作作为新条目追加；项目配置把 `effects.overtime` 设为 `false` 时关闭。时机：带 `estimate` 的 `todo` 调用的同步守卫阶段。实例：`src/pipeline.ts` 的 `overtimeLock`，错误 `Task "…" (t1) already received an overtime warning, so its 10-minute estimate is closed and estimate cannot change it. …`。
  - 项目尾项 — 功能：调用开启列表或新一轮时，把项目配置里作用到当前代理的 `tailItems` 按声明顺序追加在本次调用自己的条目之后——`main` 只在主会话，`isolated` 还包括在自己 worktree 里工作的子代理，`all` 是所有持有 `todo` 的代理——每项放进自己的 `phase`，以 `detail` 为说明、`minutes` 为估算（未设置时取 15 与 `leafMaxMinutes` 中较小者；显式设置的值不受 `leafMaxMinutes` 限制），并在说明记录中记下 `tailRule` `{ ruleId, protected }`，会话重载与 `/todo-ng` 编辑后都保留；视图把这类条目标为 `project rule "<id>"` 与 `protected`。`add` 与尾项标题重复时整次调用被拒。受保护的尾项不能放弃；当前规则带 `check` 的尾项，在本次调用之后仍有尾项以外的条目处于待处理或进行中时不能完成；其规则已从配置中删除或文件已删除时，可以完成并附一条说明。时机：开启列表或新一轮的 `todo` 调用，以及 `drop_ids`/`done_id` 指向尾项时。实例：`src/tail.ts` 的 `appendTailItems`/`tailLifecycleGuard`，错误 `Task "All tests pass" is appended automatically by project tail rule "tests": remove it from add` 与 `Task "All tests pass" (t3) is a protected tail item from project rule "tests": it cannot be dropped, complete it instead`。
  - 尾项验收检查 — 功能：`done_id` 完成一个当前规则带 `check` 的尾项时，把检查作为验收守卫运行（在完成提交之前），未通过则条目保持未完成，调用以 `isError` 失败。`shell` 检查经 omp 原生 shell 运行 `command`（不派生 `sh`/`bash` 子进程），工作目录是会话目录，超时取规则的 `timeoutMs`，并接收工具调用的 `AbortSignal`；只有退出码 0 算通过，非零退出、没有退出状态、超时或取消都被拒，拒绝信息给出原因与输出的最后 4000 个字符，每次运行都记录退出码与耗时。`judge` 检查依次询问模型角色 `@omp-todo-ng`（仅显式绑定时）与 `default` 的模型，出错的模型跳过；提问内容是作为验收条件的 `prompt`，加上该条目、本次完成之前的列表，以及会话目录的 git `status --short`、`diff --stat HEAD` 与 `log --oneline -5`；只有回答中含一个 JSON 对象 `{"verdict":"pass","reason":…}` 才算通过（对象前后的文字不计）。没有绑定在线模型、判定为 `fail`、回答无法解析、所有模型都失败、到达 `timeoutMs` 或被取消，一律拒绝。没有检查的条目——工作条目、所属规则不带 `check` 的尾项、规则已从配置删除的尾项——两种检查都不运行。时机：`done_id` 完成这类尾项的 `todo` 调用的验收阶段。实例：`src/acceptance.ts` 的 `acceptanceGuard`/`runShellCheck`/`judgeVerdict`，在 `index.ts` 的 `executeTodo` 中接入；错误 `Task "Verify" (t2) stays open: the check of project rule "verify" did not pass: \`bun test\` exited with 1 in /repo.`
- **完成时提交**
  - 完成即提交 — 功能：每次调用只用 `done_id` 完成一个条目，因为一次完成最多对应一个提交；`commit.message` 提交宿主变更记录归属于本代理及其子代理的改动，带 `commit.paths` 时提交这些 git pathspec（从会话目录解析）里的全部改动，经宿主在私有 index 上的选择性提交完成，其他写入者暂存或未暂存的改动原样保留，并在条目上记录 `{sha, message, scope}`。提交作为调用的最后一个守卫执行，在校验与其余守卫全部放行之后；提交失败则整次调用被拒，条目保持未完成。项目配置把 `effects.commit` 设为 `false` 时，完成既不提交也不被拒绝，传入的 `commit` 子句被忽略并附一条说明。时机：`done_id` 完成一个未关闭条目的 `todo` 调用。实例：`{ done_id: "t2", commit: { message: "feat: add export", paths: ["src/export.ts"] } }` → `Committed 1a2b3c4 "feat: add export" (src/export.ts)`，经 `src/commit-guard.ts` 的 `commitGuard`/`completeWithCommit` 与 `src/git.ts` 的 `commitCompletion`；关闭提交时附 `The project config turns completion commits off (effects.commit is false): the commit clause was ignored and nothing was committed.`
  - `Model:` trailer — 功能：按首次出现顺序，为会话自上次 todo 提交以来回答过的每个模型和当前模型各追加一行 `Model: <provider>/<id>`。时机：完成时产生的每个提交。实例：`src/models.ts` 的 `commitMessage`/`participatingModels` 写出 `Model: anthropic/claude-opus-5-5`。
  - 未提交改动拒绝完成 — 功能：本代理在检出目录里有未提交改动，或会话没有变更记录且检出目录有改动时，拒绝不带 `commit` 的 `done_id`；只有其他写入者的改动不会触发，项目配置中的 `effects.commit: false` 会关闭它。时机：`done_id` 不带 `commit` 完成一个未关闭条目的 `todo` 调用。实例：`src/git.ts` 的 `workState`，错误 `Task "Implement" (t1) would leave this agent's uncommitted work in /repo: call todo again with commit ({ message }) …`。
  - 共用父 worktree 豁免 — 功能：cwd 位于父代理 git worktree 内的子代理完成条目时不提交、也不被拒绝，忽略 `commit`，由父代理整合并提交；位于自己 linked worktree 的子代理照常提交。时机：父会话可经 `AgentRegistry` 找到的子代理每次完成条目时。实例：`src/session.ts` 的 `parentCwdOf`，`src/git.ts` 的 `worktreeScope`，提示 `Shared worktree with the parent agent (/repo): this completion committed nothing; …`。
- **会话分支上的列表状态**
  - 宿主列表与说明记录 — 功能：列表的阶段、标题、顺序与状态只存在宿主的列表里（live 为 `session.getTodoPhases()`；分支上为最新 `todo` 结果的 `details.phases`，或者工具经 eval 调用时宿主代替 `todo` 结果记下的 `user_todo_edit` 条目），插件只把宿主存不下的部分——目标、条目 ID、说明、估算、进度时间、提交记录与项目尾项的规则绑定——记为 `mouriya.omp.todo-more.notes` 条目，只在并入那一步按阶段名与标题挂接到宿主条目，此后一律以 ID 识别条目；`todo` 调用写宿主列表，仅在说明记录变化时追加该条目；`/todo-ng` 保存同样如此（`commitTodoState`），改目标或说明时宿主列表内容不变。在 `todo` 调用结束与其结果落到分支之间读取的读者（`edit` 门、规划快照、评审读取、停止时的提醒判断、尚未落盘的宿主提醒内容）读 `liveState`，`/todo-ng` 面板与 HUD 也读它。`todo` 结果里的 `details.more` 快照只供该结果自己的卡片渲染。时机：每次被接受的 `todo` 调用与 `/todo-ng` 保存之后。实例：`src/commit.ts` 的 `commitTodoState`/`liveState`，`src/state.ts` 的 `joinHost`/`toNotes`。
  - 分支折叠 — 功能：每次读取都在分支条目上向前折叠——把最新的宿主列表（来自 `todo` 结果或 `user_todo_edit` 条目）按阶段名与标题并入最新说明记录，给没有说明记录的宿主条目分配新 ID、不带说明与估算——连同 ask 等待、超时警告与计划提醒投递记录一起折叠，并为每个 session manager 保留一个增量累加器。时机：提醒、UI 或超时事实每次读取列表时。实例：`src/branch.ts` 的 `foldEntry`/`branchFacts`。
  - 时间跟踪 — 功能：跟踪每个条目 `in_progress` 墙钟时间并排除 `ask` 等待，按状态保存每个条目的进度（待处理：首次开始与暂停时刻；进行中：首次开始与运行时钟；已完成或已放弃：首次开始与关闭时刻），仅在条目开始（`in_progress`）时将剩余预算转换为目标完成时刻（`due by HH:MM`；跳过/暂停时停止计时且不展示过期截止时刻，恢复时按剩余预算重新转换；未开始条目不转换截止时刻），并为每个 estimate 记录预算 id，使超时警告在重新估算后仍锁定该预算身份。时机：每次分支折叠、状态结算与超时检查时。实例：`src/state.ts` 的 `elapsedOf`/`dueAt`/`transition`，`src/format.ts` 的 `itemTimeSummary`，等待从 `tool_execution_start` 记录折叠，见 `src/branch.ts`。
- **编辑型子代理中的 `todo` 恢复**
  - 子代理 `todo` 恢复 — 功能：为启用工具中含 `edit` 但不含 `todo` 的子代理会话补回 `todo`，按规范顺序（内置工具按注册表顺序，其余按码点排序）写整份启用集使 fork 保持 prompt 缓存；工具受限会话经 `refreshRpcHostTools` 安装。项目配置把 `effects.editGate` 设为 `false` 时不补回；项目配置无效时照常补回。时机：子代理会话每次模型调用之前，通过在其首个 `before_agent_start` 上挂接的 before-model-call 钩子。实例：`index.ts` 的 `guardSubagent`/`restoreTodo`，其中 `canonicalToolOrder` 来自 `omomp-shared/active-tools.ts`。
- **计划与提醒**
  - eager 前导内容 — 功能：宿主按 `todo.eager`（`preferred` 或 `always`）发出隐藏的 eager 前导时，把文字换成插件的结构化 `todo` 调用指令（`goal` 与带 `phase`、`title`、`detail`、`minutes` 的 `add`）；何时出现由宿主决定，包括自动压缩之后。时机：`context` 钩子里类型为 `eager-todo-prelude` 的消息。实例：`src/reminders.ts` 的 `eagerTodoText`/`hostReminderOf`。
  - 编辑守卫 — 功能：todo 列表没有未完结条目时（列表为空，或全部条目已完成或放弃），在宿主的 `tool_call` 事件里拦下 `edit` 调用，分别以初始化提醒或本轮已完结的提醒为原因，不改动宿主的 `edit` 工具。项目配置 `effects.editGate: false` 时关闭该守卫；项目配置无效期间，无论有无未完结条目，每次 `edit` 都被拦下并给出配置文件路径与原因。同一条 assistant 消息里排在 `edit` 前面的 `todo` 调用（宿主在执行任何调用之前就发出整条消息的全部 `tool_call`）计入：其参数通过 `todo` 自己的 schema 与规则检查，且结果列表含 `pending` 或 `in_progress` 条目即可，调用只检查、不执行。时机：主会话或子代理每次 `edit` 的 `tool_call`；前面的 `todo` 调用在它们各自的 `tool_call` 上检查。实例：`src/planning.ts` 的 `registerPlanning` 以 `Todo is empty. Work phase … call todo with goal` 或 `Every item of this todo round is completed or abandoned, so the round is over. …` 拦下，`src/tool.ts` 的 `previewTodo` 按项目配置运行同样的规划、尾项变换与同步守卫，不运行验收与提交守卫；配置无效时以 `Project config /repo/.omp/todo-ng.json is invalid: … Fix the file before retrying edit.` 拦下。
  - 计划提醒 — 功能：投递带当前时间的 `<system-reminder source="omp-todo-ng/planning">`——列表为空时是 `goal` + `add` 指令；全部条目已完成或放弃时是用 `goal` + `add` 开始新一轮的指令；新用户 prompt 语义状态变化或人工经 `/todo-ng` 带外编辑时投递紧凑活跃视图（目标、总进度、已关闭阶段计数、当前 `in_progress` 项完整说明与截止时刻、`pending` ID 与标题索引、带外编辑的高亮说明与 `todo({})` / `todo({ view })` 查询提示）；压缩或分支切换丢弃前文上下文后，一次性恢复完整无删减纯文本列表（含全部已完成与已放弃项的说明与进度时间；全部条目已关闭时以开始新一轮的指令开头）；跳过 `todo` 自身工具结果后的重复注入，且纯墙钟流逝不触发重发。每次投递都追加一条记录所投递状态键的 `mouriya.omp.todo-more.planning` 条目；分支折叠读取这些条目、压缩与分支摘要条目以及 `todo` 结果，判断模型最近看到的列表和是否需要恢复。时机：语义状态变化或压缩后的 `before_agent_start` 隐藏消息，以及仅在运行中压缩恢复或带外编辑时作为 `tool_result` 的 `additionalContext`。实例：`src/planning.ts` 的 `registerPlanning`，`src/state.ts` 的 `semanticStateKey`，`src/branch.ts` 的 `foldPlanning`，`src/format.ts` 的 `formatCompactView`/`formatFullView`。
  - 停止提醒内容 — 功能：宿主发出停止提醒（`todo.reminders`，最多 `todo.remindersMax` 次，主会话与子代理一视同仁）时，把文字换成插件的：当前时间、每个未完成项连同 ID、说明与时刻状态（活跃项 `due by`、暂停项 `paused`、未开始不转换截止时刻）、目标（没有时提示传 `goal`），以及缺说明条目的 `explain` 提示。内容取自提醒在分支中所处位置时的列表与消息时间戳，因此后续请求里字节不变。时机：`context` 钩子里形如宿主 `You stopped with N incomplete todo item(s)` 提醒的 developer 消息。实例：`src/reminders.ts` 的 `contextMessages`/`reminderText`，以及 `src/branch.ts` 的 `foldBranchAt`。
  - 延迟截断催促 — 功能：主会话被截断收场（provider 错误、工具调用未完成、非人为 abort，用户自己的中断不算）时，若宿主的 `todo.reminders` 开启，且最近一条真实用户消息之后插件提醒少于 `todo.remindersMax` 条，就在 10 秒宽限后催促；一旦出现轮次、排队消息或编辑器草稿即取消，并加闩使停滞的链只催一次，直到有进展再重新装填。宿主在这类停止上不会提醒。项目配置把 `effects.cutOff` 设为 `false` 或配置无效（记一条警告）时什么都不装填——没有宽限催促，也没有配额等待与小组件；宿主的停止提醒及其文字改写不受影响。时机：主会话 `agent_end`。实例：`src/reminders.ts` 的 `armCutOff`/`CUT_OFF_GRACE_MS`/`continuation`，由 `agent_start`、`session_shutdown`、`session_switch`、`session_branch`、`session_tree` 取消。
  - 配额 429 等待 — 功能：停止原因是用量上限 429 时把截断提醒推迟到账户重置后一分钟（用 provider 重试提示，否则用 omp 对耗尽配额的 30 分钟估算），在编辑器上方显示一行小组件标明发送时间，编辑器有草稿时等到草稿清除。时机：`agent_end` 决定的截断等待之内。实例：`src/quota-wait.ts` 的 `cutOffWait`/`quotaNoticeLine` 渲染 `Todo reminder scheduled for 14:35 (account quota 429, resets 14:34) · Ctrl+N or /todo-ng-cancel to cancel`，widget key `todo-ng.quota-reminder`。
  - `/todo-ng-cancel` 与 `Ctrl+N` — 功能：注册该命令与快捷键取消待发的延迟提醒，把链闩为已取消并通知 `Todo reminder cancelled` 或 `No pending Todo reminder`。时机：用户按 `Ctrl+N` 或运行 `/todo-ng-cancel` 时。实例：`src/reminders.ts` 的 `pi.registerShortcut("ctrl+n", …)` 与 `pi.registerCommand("todo-ng-cancel", …)`。
  - mid-run nudge 内容 — 功能：宿主发出执行中途 todo 提醒（`todo.midRunNudges` 为 `capped` 或 `backoff`，12 次及以上修改类工具结果而其间没有 `todo` 调用）时，把文字换成列出未完成数与目标的版本。时机：`context` 钩子里类型为 `mid-run-todo-nudge` 的消息。实例：`src/reminders.ts` 的 `midRunNudgeText`。
  - goal 模式 `<todo_context>` — 功能：把每条带宿主 todo 快照的 `goal-mode-context` 消息里的快照，换成该消息在分支中所处位置时插件更丰富的快照（目标、状态、说明、估算）。时机：此类消息在上下文中时的每次模型调用的 `context` 钩子。实例：`src/reminders.ts` 的 `contextMessages`/`goalTodoContext`。
  - 提醒渲染器 — 功能：把提醒事件渲染为只有事件头（未完成数 · 第几次/上限）的警告卡片，使转录卡片不再重复列出 todo 条目。时机：转录渲染 `mouriya.omp.todo-more.reminder` 消息时。实例：`src/reminders.ts` 的 `pi.registerMessageRenderer(REMINDER_TYPE, renderReminder)`。
- **超时警告**
  - 超时截止定时器 — 功能：保持一个指向最近活动条目估算截止时间的定时器，条目取自 live 宿主列表并带上说明记录里的计时，在会话/分支事件、`todo`/`ask` 结果与轮次/运行结束时重新武装，`ask` 打开期间暂停。项目配置把 `effects.overtime` 设为 `false` 或配置无效（记一条警告）时不保留定时器，也不发警告。时机：从 `session_start`/`session_switch`/`session_branch`/`session_tree` 与每个改变列表的事件调度。实例：`src/overtime.ts` 的 `registerOvertime`/`reschedule`。
  - 超时警告投递 — 功能：到点时按预算 id 发送一条 `mouriya.omp.todo-more.overtime` 消息——运行中作为 aside、空闲时作为不开轮次的可见消息——包在 `<system-reminder source="omp-todo-ng/overtime">` delta 中，携带当前时间与已超过的目标完成时刻，记录下的消息即分支折叠的持久警告事实。时机：被跟踪条目的 in_progress 墙钟时间超过其估算时。实例：`src/overtime.ts` 的正文 `Current time: 2026-11-22 10:31\nSERIOUS: todo item "…" is past its target completion time of 10:30 (overdue as of 10:31).`，经 `createDeltaStream("omp-todo-ng/overtime")` 发送。
- **原生 UI 与 Tern 面板**
  - `todo-ng.hud` 小组件 — 功能：在编辑器上方挂载扩展所在会话的实时 pi-tui 节点（omp 把它放在活动行正前方）——pill、进度及打开富 popover（带编辑按钮）的 disclosure——在工具结果、轮次、压缩与 `/todo-ng` 保存之后重绘，并在会话、分支与树跳转时重装。纯终端里宿主不为它绘制任何内容；在 Tern 中它就是原生 pill。时机：`session_start`/`session_switch`/`session_branch`/`session_tree`。实例：`src/ui.ts` 的 `hudController`/widget key `todo-ng.hud`。
  - `/todo-ng` 命令与编辑器 — 功能：注册该命令打开覆盖层面板，显示目标与清单，带「编辑目标」、每个条目一个「编辑说明」按钮和「关闭」（Tab/方向键选择，Enter 编辑，Escape 关闭）；编辑时打开表单（`formDialog`，宿主没有表单时每个字段一个 `editor` 对话框），经与工具相同的路径保存，再在更新后的列表上重新打开面板，编辑被拒时通知原因。非交互会话以 `todo-ng.ui-unavailable` 消息拒绝；会话切换、分支或树跳转时关闭面板。时机：`/todo-ng` 或 HUD 编辑按钮。实例：`src/ui.ts` 的 `pi.registerCommand("todo-ng", …)`、`panelView`/`goalFormHtml`/`applyGoalForm`，消息 `Todo NG editor requires an interactive UI.`。
  - Tern 包 — 功能：随包发布 `tern/plugin.toml`（id `omp-todo-ng`）、`window.luau` 与 `todo-ng.css`，其样式表把扩展小组件所在的行叠放到 omp 的活动行上，并在那里隐藏原生 Todo HUD、保留其布局盒，使药丸占据原生药丸的位置，不新增一行，也不改变 Tern 的 flex dock；活动行未显示时，该行自成一行。时机：Tern 中该插件已安装且启用期间。实例：`tern/todo-ng.css` 中的 `.sf-dock[data-surface="omp.session"]` 规则。
  - Tern owner-CLI 安装 — 功能：加载时经 `tern plugin dir/list/install --json` 安装或修复该包，副本一致时跳过，Tern 存在但检查失败时拒绝整个扩展工厂。时机：异步工厂内、订阅 review API 之前；`tern` 不在 `PATH` 上时跳过。实例：`src/tern-plugin-install.ts` 的 `initializeTernPlugin`/`isCurrent`。
- **同步 review 协议**
  - `omp-todo-ng:read` 监听器 — 功能：在事件总线上同步应答请求 `{agentId, reply(value)}`：从指定 agent 的活动分支读取并回复 `{kind: "ok", goal, openItems, counts}` 或 `{kind: "unavailable"}`，不写、不缓存、无定时器。时机：另一进程内扩展在 `pi.events` 上发出 `omp-todo-ng:read` 时；`session_shutdown` 时移除。实例：`src/review-api.ts` 的 `registerReviewApi`，协议见 `omomp-shared/todo-read.ts`。
- **插件设置与项目配置**
  - 插件设置 — 功能：以原生插件设置声明 `leafMaxMinutes`（默认 `60`，1–1440），非法值回退默认并告警；todo 提醒、提醒上限与 eager 前导都跟随宿主的 `todo.*` 设置。时机：每次 `todo` 调用经 `getPluginSettings` 重读。实例：`package.json` 的 `omp.settings`、`src/settings.ts` 的 `readSettings`；用 `omp plugin config omp-todo-ng` 设置。
  - 项目配置文件 — 功能：从会话目录所在 git 仓库的根（不在 git 中时就是会话目录本身，不向上合并父目录）读取项目的 `.omp/todo-ng.json` 并严格解析：`effects`（`editGate`、`commit`、`overtime`、`cutOff`，各自默认 `true`）与 `tailItems`（`id`、`title` 不可重复，`detail`，可选 `phase` 默认 `Verification`、`minutes` 1–1440、`scope` 取 `main`/`isolated`/`all` 默认 `main`、`protected` 默认 `true`、`check` 为 `{ kind: "shell", command, timeoutMs ≤ 600000（默认 120000）}` 或 `{ kind: "judge", prompt, timeoutMs ≤ 300000（默认 30000）}`）；没有文件时全部取默认。文件读不出、不是 JSON、出现未知键或越界取值、尾项 `id` 或 `title` 重复时，所有 `todo` 变更都失败、所有 `edit` 调用都被拦下，并给出文件路径与原因，同时记一条警告；`todo({})` 与 `todo({ view })` 照常返回并附上同一原因；文件能解析之前，超时警告与截断催促都停止。`leafMaxMinutes` 仍是插件设置。时机：每次 `todo` 调用、每次 `edit` 的 `tool_call`、子代理每次模型调用、每次超时重排与每次截断判断都重新读取，改完文件后下一次即生效。实例：`src/project-config.ts` 的 `readProjectConfig`，错误 `Project config /repo/.omp/todo-ng.json is invalid: effects.editgate: must be removed. Fix or remove the file: todo changes are refused until it parses.`
- **语言解析**
  - UI 文本语言 — 功能：把所有面向人的字符串（工具标签、命令说明、HUD、编辑器、通知）按 `OMOMP_LANG` 解析为英文或中文，其次取 `LC_ALL`/`LC_MESSAGES`/`LANG`，否则英文，每次生成时重读，面向模型的文本保持英文。时机：插件每次产出 UI 文本或注册标签时。实例：`src/reminders.ts` 的 `tr("Cancel the pending Todo NG reminder", "取消待发的 Todo NG 提醒")`，`tr` 来自 `omomp-shared/i18n.ts`。
