# omp-todo-more

English | [简体中文](README.zh-CN.md)

- **The `todo` tool**
  - `todo` tool registration — Does: registers a tool named `todo` that shadows the host's built-in tool, parsing one Todo document per call into commands (`INIT`, `PHASE`, `ADD`, `START`, `DONE`, `DROP`, `RM`, `EXPLAIN`, `ESTIMATE`, `GOAL`, `VIEW`) over a phased list with a goal, per-item explanations and minute estimates. When: whenever the model calls `todo` in a session where the plugin is loaded. Example: `pi.registerTool(TODO_TOOL_DEFINITION)` in `index.ts`; a call is `*** Begin Todo\nINIT "objective" "measure" "doneWhen"\nPHASE "Implementation"\nADD "Implement the parser" "Accept complete documents" 20\n*** End Todo`.
  - Tool field declarations — Does: declares `loadMode: "discoverable"`, `approval: "read"`, `strict: true`, `concurrency: "exclusive"` and `mergeCallAndResult: true`, so the tool is discoverable, strictly validated, serialized and its result card replaces the call card. When: fixed at tool registration on plugin load. Example: `TOOL_FIELDS` in `index.ts`.
  - Description and card rendering — Does: carries a model-facing description of the document grammar and rejection rules, plus `describeCall`/`describeResult` and `renderCall`/`renderResult` hooks that paint ANSI and native cards previewing the accepted command lines and unfinished tail. When: in the tools section of the prompt whenever `todo` is offered, and when a `todo` call or result card renders. Example: `DESCRIPTION` in `src/tool.ts`, `renderTodoCall`/`renderTodoResult` from `src/render.ts`.
  - Document validation — Does: validates the whole document before applying anything and rejects the entire batch on the first error: JSON-quoted strings, unique titles, `ADD "title" "explanation" <positive integer minutes>` capped by `leafMaxMinutes`, `ESTIMATE` refused on an item that already received an overtime warning. When: on every `todo` call, before any state change. Example: `ruleErrors`/`overCap` in `src/tool.ts` produce `Task "…" estimate 90 min exceeds the 60-minute limit for one item`.
  - `xd://todo/protocol` — Does: serves the `protocol` doc topic covering document grammar, selectors and completion commits. When: when the model reads `xd://todo` or `xd://todo/protocol`. Example: `todoDocTopics` in `src/topics.ts` loads `src/topics/todo-protocol.md`.
  - `xd://todo/lifecycle` — Does: serves the `lifecycle` doc topic covering planning, waits and time budgets. When: when the model reads `xd://todo` or `xd://todo/lifecycle`. Example: `todoDocTopics` in `src/topics.ts` loads `src/topics/todo-lifecycle.md`.
- **Git association of a completion**
  - `DONE` commit clause — Does: commits through the host's selective commit (`createDraft`/`commitSelection`) on a private index — one string commits only the lines the host's change journal attributes to this agent and its subagents, two strings are a whitespace-separated git pathspec scope (resolved by git from the session directory, so `.`, `*.ts` and `dir/*.ext` mean what they mean to `git add`) and message whose paths are committed whole — records sha/message/scope on the item, never takes another writer's changes outside the commit, rebuilds on a moved HEAD when the selection still applies and otherwise fails naming the move, refuses a clause-less `DONE` only when this agent has uncommitted work, and in a session without a change journal fails the message-only form and asks for paths. When: when a `DONE` command executes inside a `todo` batch. Example: `DONE "Render the preview" "src/render.ts" "Show streamed intent"` handled by `completeWithCommit` in `src/tool.ts` and `commitCompletion` in `src/git.ts`.
  - `Model:` trailers — Does: appends one `Model: <provider>/<model-id>` trailer per model the committing session ran since its previous todo commit, plus the current model, each once in order of first use. When: at every commit a `DONE` makes. Example: `commitMessage` in `src/models.ts`; read back with `git log --format='%(trailers:key=Model,valueonly)'`.
  - Parent-worktree exemption — Does: exempts a subagent whose working tree is its parent's — found through `ctx.agent.parentId` — from committing and from the uncommitted-work refusal, because the parent integrates that worktree. When: on every `DONE` executed by a `task:*` subagent. Example: `parentCwdOf` in `index.ts`, worktree sharing compared in `src/git.ts`.
- **List state on the session branch**
  - Snapshot entries and host projection — Does: appends a full `mouriya.omp.todo-more` snapshot entry to the session branch on each accepted mutation, confirms acceptance, then pushes the host projection (title as content, the same four statuses) into `TodoTracker` so the host HUD, `/todo`, rehydration and persistence keep working. When: after every accepted `todo` call and GUI save. Example: `appendCustomEntry(TODO_MORE_ENTRY_TYPE, toSnapshot(next))` and `session.setTodoPhases(hostPhases(next))` in `src/commit.ts`.
  - Branch fold — Does: folds every read forward over the branch entries — joining host `user_todo_edit` records (`/todo`, RPC `set_todos`, subagent auto-complete) by title and marking new titles as lacking explanation and clock — keeping one incremental accumulator per session manager. When: on every read of the list by the tool, reminders, overtime or the UI. Example: `foldEntry`/`branchFacts` in `src/branch.ts`.
  - Time tracking — Does: tracks per-item `in_progress` wall time with `ask` waits excluded, recording a budget id per estimate so an overtime warning latches to that budget identity across re-estimates. When: during each branch fold and each overtime check. Example: `elapsedTime`/`transitionTime` in `src/state.ts`, waits folded from `tool_execution_start` records in `src/branch.ts`.
- **`todo` restoration in editing subagents**
  - Subagent `todo` restoration — Does: puts `todo` back into a subagent session whose enabled tools include `edit` but not `todo`, writing the active set in canonical order (builtins in registry order, then the rest sorted by code point) so forks keep the prompt cache; tool-restricted sessions get it via `refreshRpcHostTools`. When: before every model call of a subagent session, via a before-model-call hook armed on its first `before_agent_start`. Example: `guardSubagent`/`restoreTodo` in `index.ts`, with `canonicalToolOrder` from `omomp-shared/active-tools.ts`.
- **Planning and reminders**
  - Eager prelude content — Does: when the host's `todo.eager` (`preferred` or `always`) makes it emit its hidden eager prelude, replaces the text with the plugin's Todo-document instruction (`INIT` objective/measure/doneWhen, `PHASE`, `ADD` with explanation and minutes); the host owns when it appears, including after an auto-compaction. When: in the `context` hook, on a message of type `eager-todo-prelude`. Example: `eagerTodoText`/`hostReminderOf` in `src/reminders.ts`, text ``Before substantive work, create a phased todo. … You MUST call `todo` first in this turn.``.
  - Edit guard — Does: blocks an `edit` call from the host's `tool_call` event while the todo list is empty, giving the init reminder as the reason, without touching the host's `edit` tool. A `todo` call that precedes the `edit` in the same assistant message — the host emits every `tool_call` of a message before executing any of them — counts when its document passes `todo`'s own parse and rule checks and leaves a non-empty list; the document is only checked, never executed. When: on every `edit` `tool_call` of a main session or subagent; the earlier `todo` calls are checked on their own `tool_call`. Example: `registerPlanning` in `src/planning.ts` blocks with `Todo is empty. Work phase … initialize with one complete Todo document`, `previewTodo` in `src/tool.ts` runs the shared parse and rule checks.
  - Planning reminder — Does: delivers a `<system-reminder source="omp-todo-more/planning">` — the `INIT` instruction while empty, otherwise a full JSON snapshot plus the "Discussion, investigation, explanation and questions add no items" preamble — through the shared delta stream, re-sent only when the snapshot changes and restored after compaction drops it. When: as a hidden `before_agent_start` message and as `additionalContext` after each tool batch. Example: `reminderBody`/`createDeltaStream("omp-todo-more/planning")` in `src/planning.ts`.
  - Stop reminder content — Does: when the host sends its stop reminder (`todo.reminders`, at most `todo.remindersMax` times, main session and subagents alike), replaces the text with the plugin's: every open item with its explanation and estimate, the goal (or a prompt to write `GOAL`) and an `EXPLAIN` hint for items without an explanation. The text comes from the list as it stood where the reminder sits in the branch, so it keeps its bytes on later requests. When: in the `context` hook, on a developer message shaped like the host's `You stopped with N incomplete todo item(s)` reminder. Example: `contextMessages`/`reminderText`/`stateAtEntry` in `src/reminders.ts` emit `You stopped with N incomplete todo item(s): … (Reminder 1/3)`.
  - Deferred cut-off nudge — Does: nudges a main-session settle that ended cut off (provider error, outstanding tool calls, non-human abort — never the user's own interrupt) after a 10-second grace when the host's `todo.reminders` is on and fewer than `todo.remindersMax` plugin reminders followed the latest real user message; the nudge is cancelled the moment a turn, queued message or editor draft appears, and latched so a stalled chain is nudged once until progress re-arms it. The host does not remind on such stops. When: armed on `agent_end` of a main session. Example: `armCutOff`/`CUT_OFF_GRACE_MS`/`continuation` in `src/reminders.ts`, cancelled by `agent_start`, `session_shutdown`, `session_switch`, `session_branch`, `session_tree`.
  - Quota-429 wait — Does: defers the cut-off reminder until one minute past the account reset on a usage-limit 429 (provider retry hint, else omp's estimate of 30 min for an exhausted quota), shows a one-line above-editor widget with the send time, and holds the reminder while a draft sits in the editor. When: inside the cut-off wait decided at `agent_end`. Example: `cutOffWait`/`quotaNoticeLine` in `src/quota-wait.ts` render `Todo reminder scheduled for 14:35 (account quota 429, resets 14:34) · Ctrl+N or /todo-more-cancel to cancel`, widget key `todo-more.quota-reminder`.
  - `/todo-more-cancel` and `Ctrl+N` — Does: registers the command and the shortcut to cancel the pending deferred reminder, latching the chain and notifying `Todo reminder cancelled` or `No pending Todo reminder`. When: when the user presses `Ctrl+N` or runs `/todo-more-cancel`. Example: `pi.registerShortcut("ctrl+n", …)` and `pi.registerCommand("todo-more-cancel", …)` in `src/reminders.ts`.
  - Mid-run nudge content — Does: when the host sends its mid-run todo nudge (`todo.midRunNudges` `capped` or `backoff`, after 12 or more mutating tool results without a `todo` call), replaces the text with one that lists the open count and the goal. When: in the `context` hook, on a message of type `mid-run-todo-nudge`. Example: `midRunNudgeText` in `src/reminders.ts` emits ``N todo items still open. If you finished a task since last `todo` update, mark it done now…``.
  - Goal-mode `<todo_context>` — Does: replaces the host's todo snapshot inside each `goal-mode-context` message that carries one with the plugin's richer snapshot (goal, status, explanation, estimate) as of that message's place in the branch. When: in the `context` hook on every model call while such a message is in context. Example: `contextMessages`/`goalTodoContext` in `src/reminders.ts`.
  - Reminder renderer — Does: renders reminder events as a bare header line (incomplete count · attempt/max) so the transcript card never re-lists the todo items. When: when the transcript renders an `mouriya.omp.todo-more.reminder` message. Example: `pi.registerMessageRenderer(REMINDER_TYPE, renderReminder)` in `src/reminders.ts`.
- **Overtime warnings**
  - Overtime deadline timer — Does: keeps one timer aimed at the nearest active item's estimate deadline, re-armed on session/branch events, `todo`/`ask` results, `commitTodoPhases` writes and turn/run ends, and standing down while an `ask` is open. When: scheduled from `session_start`/`session_switch`/`session_branch`/`session_tree` and every list-changing event. Example: `registerOvertime`/`reschedule` in `src/overtime.ts`.
  - Overtime warning delivery — Does: at the deadline sends one `mouriya.omp.todo-more.overtime` message per budget id — an aside mid-run, a visible no-turn message while idle — wrapped in a `<system-reminder source="omp-todo-more/overtime">` delta, with the recorded message as the durable warning fact the branch folds. When: when a tracked item's in_progress wall time passes its estimate. Example: body `SERIOUS: todo item "…" has exceeded its estimated time: estimate 60 min; elapsed 62.31 min of in_progress wall time.` in `src/overtime.ts`, sent with `createDeltaStream("omp-todo-more/overtime")`.
- **Native UI and Tern panel**
  - `todo-more.hud` widget — Does: mounts a live `TodoHud` below the editor following the viewed session — pill, progress and a disclosure opening the rich popover — and re-installs on session, branch and tree transitions. When: on `session_start`/`session_switch`/`session_branch`/`session_tree`. Example: `installHud`/widget key `todo-more.hud` in `src/ui.ts`.
  - `/todo` input rewrite — Does: rewrites interactive `/todo` and `/todo edit` input to `/todo-more` on a native frontend, leaving the other `/todo` subcommands to the host. When: on `input` events matching `/^\/todo(?:[\s:]+(.*))?$/` when native rendering is active. Example: the `input` hook in `src/ui.ts` returns `{ text: "/todo-more" }`.
  - `/todo-more` command and editor — Does: registers the command that opens the session-bound overlay editor (`TodoPanel`) for goal fields and item explanations, rejecting non-interactive sessions with a `todo-more.ui-unavailable` message and discarding drafts when the viewed session changes. When: on `/todo-more`, the HUD edit affordance or the `/todo` rewrite. Example: `pi.registerCommand("todo-more", …)`/`TodoPanel` in `src/ui.ts`, message `Todo More editor requires an interactive UI.`
  - Tern bundle — Does: ships `tern/plugin.toml` (id `omp-todo-more`), `window.luau` and `todo-more.css`, whose stylesheet hides the native Todo HUD while keeping its layout box so the extension's widget takes the slot. When: while the Tern plugin is installed and enabled. Example: `.sf-dock[data-surface="omp.session"]` grid adapter in `tern/todo-more.css`.
  - Tern owner-CLI install — Does: installs or repairs the bundle through `tern plugin dir/list/install --json` at load, skipping a matching copy and rejecting the extension factory when Tern is present but the check fails. When: inside the async factory before the review API is subscribed; skipped when `tern` is not on `PATH`. Example: `initializeTernPlugin`/`isCurrent` in `src/tern-plugin-install.ts`.
- **Synchronous review protocol**
  - `omp-todo-more:read` listener — Does: answers event-bus requests `{agentId, reply(value)}` synchronously from the named agent's live branch with `{kind: "ok", goal, openItems, counts}` or `{kind: "unavailable"}`, with no writes, cache or timers. When: whenever another in-process extension emits `omp-todo-more:read` on `pi.events`; removed on `session_shutdown`. Example: `registerReviewApi` in `src/review-api.ts`, protocol in `omomp-shared/todo-read.ts`.
- **Plugin settings**
  - Plugin settings — Does: declares `leafMaxMinutes` (default `60`, 1–1440) as a native plugin setting, an invalid value falling back to the default with a warning; the todo reminders, their limits and the eager prelude follow the host's `todo.*` settings. When: re-read via `getPluginSettings` on each `todo` call. Example: `omp.settings` in `package.json`, `readSettings` in `src/settings.ts`; set with `omp plugin config omp-todo-more`.
- **Language resolution**
  - UI text language — Does: resolves every human-facing string (tool labels, command descriptions, HUD, editor, notices) to English or Chinese from `OMOMP_LANG`, then `LC_ALL`/`LC_MESSAGES`/`LANG`, else English, re-read on each generation while model-facing text stays English. When: whenever the plugin emits UI text or registers labels. Example: `tr("Cancel the pending Todo More reminder", "取消待发的 Todo More 提醒")` in `src/reminders.ts`, `tr` from `omomp-shared/i18n.ts`.
